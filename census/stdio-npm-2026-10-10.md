# stdio npm cohort — 16 popular MCP server packages, probed via their real `npx` launchers

**2026-10-10, `mcp-era-probe/0.5.0` (stdio + `--bogus-check`).** Cohort = the npm
packages a developer would actually `npx`-install, selected by npm weekly downloads
(top of an npm-search sweep over "mcp server" / "model context protocol", downloads
per package via api.npmjs.org). Each package was `npm install`-ed into a throwaway
prefix and probed through its real bin launcher over stdio, with the fictional-era
control (`1999-01-01`, `2099-01-01`). **Every probe ran under a scrubbed environment**
(`env -i` + throwaway HOME/TMPDIR/npm cache, cwd outside the workspace) — no host
secrets in reach of package code. Raw per-package probe output + the driver script
(`stdio-census.sh`) are in this directory.

## Headlines

1. **0/16 blind echo.** The impossible-version echo class (typescript-sdk#2977's
   decorative-negotiation variant) did NOT appear among popular npm packages. It
   lives in custom wrapper launchers (the @autenai 0.1.3 setup shim) and in the
   hosted HTTP cohort (6/78 blind echo on 2026-10-10).
2. **9/16 negotiate known eras verbatim, then answer fictional eras with a fallback**
   — which the MCP spec (basic lifecycle) explicitly permits ("if the server does not
   support the requested version, respond with another version it supports"). This is
   the important nuance vs the echo class: the response still carries true
   information (the server's real latest), and 8/9 answer fictional eras with their
   own latest rather than mirroring the request. The protocolVersion field is only
   *validation-free* here, not false.
3. **1/16 constant-answer (scryfall-mcp-server):** answers every era — real or
   fictional — with a pinned 2024-11-05. The field never varies with the request;
   negotiation is fully decorative. v0.5 adds the explicit `constant-answer` verdict
   for this shape (fixture: `fixtures/stdio-constant-answer.js`).
4. **6/16 spawn-fail without credentials** (Microsoft, Currents, Sentry, Apify,
   ZenCoder, winor30) — could not be probed anonymously; recorded honestly rather
   than guessed.
5. **16/16 fail `--strict`:** none serves the 2026-07-28 era verbatim. Same result as
   the hosted HTTP cohort on the same day (0/78): the newest MCP era is, as of this
   census, unserved everywhere we could look — HTTP *and* stdio.

## Notes
- The @autenai/mcp 0.1.4 row is a live control from the public thread where that
  package's 0.1.3 shim bug was reported: our v0.4 stdio bogus-check independently
  confirmed their fix (verbatim on known eras, fallback on fictional, no echo).
- "negotiates-known + bogus-fallback" is the honest verdict shape; treating
  spec-compliant fallback as "suspicious" would be wrong, but it does mean a client
  cannot learn from the handshake whether the server *read* the requested version —
  the definitive check remains behavioral (does the session actually speak the era).
